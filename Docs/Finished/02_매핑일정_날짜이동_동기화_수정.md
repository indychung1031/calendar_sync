# 02. 매핑된 일정 날짜·시간 이동 동기화 수정

> **상태**: ✅ 구현 완료 (2026-08-04)  
> **작성일**: 2026-08-04  
> **관련**: `claude.md` 동기화 정책 — 매핑된 일정의 윈도우 밖 날짜 이동 전파

## 1. 배경·문제

이미 `event_map`에 연결된 일정의 날짜·시간을 Google 또는 Outlook에서 바꾸면 다음이 발생했다.

| # | 증상 | 심각도 |
|---|------|--------|
| A | Outlook에서 미래→과거로 옮김 → Google에 영구히 반영 안 됨 | 치명 |
| B | Google에서 과거로 옮긴 직후 Outlook lastModified가 map과 다르면 → Google이 미래로 되돌아감 | 높음 |
| C | A 불일치 후 Google만 편집 → Outlook의 과거 이동이 취소됨 | 높음 |
| D | 윈도우 밖 Google 일정 삭제 → Outlook에 삭제 미전파 | 중간 |
| E | 수정 시각 문자열 `>=` 비교로 충돌 승자 오판 | 낮음 |

### 원인 요약

1. Google `list_events`가 `updatedMin`과 함께 `timeMin`/`timeMax`를 항상 적용 → 과거로 옮긴 일정이 feed에서 빠짐  
2. 기존 reconcile이 **한쪽만** feed에 있을 때만 ID 조회 → Outlook 과거 이동은 **양쪽 feed 부재**라 skip  
3. `_apply_*`가 reconcile보다 **먼저** 실행 → 미래 본문으로 과거 이동을 덮을 수 있음  
4. 수정 시각을 정규화 없이 문자열 비교

## 2. 구현 요약

- `Programs/sync/timestamps.py`: 수정 시각 datetime 비교 (`modified_equal` / `modified_gte`)
- `_reconcile_mapped_events`를 apply보다 **선처리**, 양쪽 feed 부재도 ID 조회 후 last-modified 전파
- 윈도우 밖 Google 삭제 → 기존 2회 확인 삭제 흐름 연결
- 단위 테스트 갱신 (87 passed)
